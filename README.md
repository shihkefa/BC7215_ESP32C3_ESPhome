# BC7215A ESPHome 空調遙控器

使用 ESP32-C3 與 BC7215A 紅外收發模組，將既有冷氣接入 Home Assistant。透過原廠離線空調碼庫產生控制訊號，也能接收原廠遙控器訊號，更新 HA 中的空調設定。

適合希望保留原廠遙控器，同時使用 HA 操作冷氣、建立排程或自動化的使用者。日常控制不依賴雲端碼庫；下載套件與首次編譯仍需要網路。

## 版本與功能

本說明適用於 **v1.0.10-fix1**，韌體日誌仍顯示 v1.0.10。

| 項目 | 說明 |
| --- | --- |
| 原廠離線碼庫 | V8.1 build 2632 |
| 配對流程 | 沿用 v1.0.7，以原廠遙控器取樣、手動切換候選 |
| 空調控制 | 開關、模式、16～30°C、風速；實際效果依冷氣與碼庫支援而定 |
| 遙控器同步 | 接收並解析原廠遙控器的溫度、模式、風速及電源設定 |
| 配對資訊 | 候選序號、候選數量、配對資料識別碼、碼庫版本 |
| 擺風 | 上下／左右分開學習，符合條件時可控制及辨識遙控器狀態 |
| 溫濕度 | SHT40 室內溫度、濕度獨立感測器 |
| 板載 RGB | 空調配對時七彩循環，其餘時間關閉 |
| 更新 | 首次 USB 安裝，後續可透過 ESPHome OTA 更新 |

> 這是紅外控制器，沒有冷氣主機的執行回報。HA 顯示的是送出的設定或收到的遙控器設定，不代表冷氣一定已收到指令。本專案不保證所有品牌、型號與附加功能相容。

## 硬體準備

- ESP32-C3-MINI-1 雙 Type-C 開發板，4 MB Flash。
- BC7215A Arduino Board V2.1 紅外收發模組。
- SHT40 I²C 溫濕度模組；範例預設啟用。
- 可傳輸資料的 USB 線、連接線及穩定電源。
- 原廠冷氣遙控器，用於配對及選用的擺風學習。
- Home Assistant 與 ESPHome Device Builder，或可執行 ESPHome CLI 的電腦。

設定以 **ESPHome 2026.8.2、Arduino framework** 為基準。不同開發板即使使用同款模組，USB 接法與 RGB 腳位仍可能不同，請核對板上標示。

## 接線

先斷電再接線，C3 與所有模組共地。本設定以 3.3V 供應兩個模組。

### BC7215A

| BC7215A 腳位 | ESP32-C3 腳位 | 用途 |
| --- | --- | --- |
| VCC／VIN | 3V3 | 模組電源 |
| GND | GND | 共地 |
| MOD | GPIO0 | 接收／發送模式 |
| BUSY | GPIO1 | 忙碌狀態 |
| TX | GPIO2 | 模組傳送 → C3 接收 |
| RX | GPIO3 | C3 傳送 → 模組接收 |

UART 設定為 **19200 bps、8N2**：8 資料位元、無同位元檢查、2 停止位元。TX 與 RX 必須交叉連接。

### SHT40

| SHT40 腳位 | ESP32-C3 腳位 |
| --- | --- |
| VCC／VIN | 3V3 |
| GND | GND |
| SDA | GPIO4 |
| SCL | GPIO5 |

範例使用 I²C 位址 `0x44`，每 30 秒更新。感測器應遠離 C3、穩壓器與其他發熱元件。溫濕度會以獨立實體顯示，沒有自動接成空調實體的目前溫度或本機恆溫控制。

如果沒有安裝 SHT40，請從 YAML 刪除 `i2c:` 區塊及 `sensor:` 下整個 `platform: sht4x` 項目，保留 Wi-Fi 訊號與運作時間項目。

### USB 與彩燈

- 範例的 WS2812 彩燈腳位為 GPIO8，可在 `substitutions.rgb_pin` 修改。
- 使用板上 USB 轉串口端（可能標示 COM／UART）時，保持 `logger_uart: UART0`。
- 使用 C3 原生 USB 端時，改為 `logger_uart: USB_SERIAL_JTAG`。
- `logger` 的 **115200** 是日誌速率；BC7215A 的 **19200 8N2** 是另一組 UART，兩者不要混用。
- GPIO2、GPIO8 為啟動相關腳位，可能出現 ESPHome strapping 警告；本設定使用這些腳位，外接電路不得妨礙正常啟動。
- RGB 設定只控制 C3 的彩燈，並不關閉 BC7215A 板上硬體指示燈。

## 安裝程式

### 1. 放置專案檔案

下載並解壓本專案，將以下內容放在同一層：

```text
專案目錄/
├── bc7215a-c3.yaml
├── secrets.yaml              # 自行建立，不上傳 GitHub
├── secrets.example.yaml
└── components/
    └── bc7215a/
        ├── __init__.py
        ├── climate.py
        ├── bc7215a_climate.cpp
        ├── bc7215a_climate.h
        └── …其餘元件檔案全部保留
```

在 HA 的 ESPHome Device Builder 環境中，通常放在 `/config/esphome/`；若安裝環境不同，請使用該 Builder 實際載入的設定目錄。可透過檔案編輯器或檔案分享工具放入元件資料夾。

**不能只貼 YAML。** 本專案使用本機外部元件，`external_components` 的 `path: components` 必須能找到完整元件資料夾。

### 2. 設定 Wi-Fi

將 `secrets.example.yaml` 複製為 `secrets.yaml`，填入：

```yaml
wifi_ssid: "你的 2.4GHz Wi-Fi 名稱"
wifi_password: "你的 Wi-Fi 密碼"
ap_password: "自行設定至少8個字元的密碼"
```

如果原本已有 `secrets.yaml`，加入或確認這三個鍵即可，不要覆蓋其他裝置的密碼。

在 `bc7215a-c3.yaml` 設定名稱：

```yaml
substitutions:
  device_name: bc7215a-c3
  friendly_name: 空調遙控器
  logger_uart: UART0
  rgb_pin: GPIO8
```

多台裝置請使用不同的 `device_name`。範例未設定 API 加密金鑰與 OTA 密碼；若自行加入，後續連線或更新時要使用相同憑證。不要將 `secrets.yaml` 或含密碼的日誌上傳至公開儲存庫。

### 3. 驗證及首次 USB 安裝

1. 啟動 ESPHome Device Builder，確認可看到 `bc7215a-c3` 設定。
2. 執行 **Validate／驗證**，先處理設定錯誤。
3. 將 C3 接上資料 USB 線，選擇 **Install／安裝**。
4. USB 插在執行 Builder 的主機時，選擇該主機的 USB 安裝方式；插在操作瀏覽器的電腦時，選擇 **Plug into this computer**，並使用支援 WebSerial 的瀏覽器，例如 Chrome 或 Edge。
5. 依畫面選擇 C3 的串口，完成編譯與上傳。不要將直接連 BC7215A 的 USB 轉 TTL 當成 C3 刷機口。
6. 若無法自動進入下載模式，可按住 BOOT、按一下 RESET，再放開 BOOT，重新嘗試。
7. 開啟日誌，確認 C3 取得 IP，並查看 BC7215A 運作狀態。

也可先選 **Manual download**，下載供首次 USB 安裝的 factory 格式韌體，再依 [ESPHome Web](https://web.esphome.io/) 流程安裝。不要把僅供 OTA 的檔案當成完整 factory 映像。

操作介面可能隨版本調整，請參閱 [ESPHome 安裝教學](https://esphome.io/install/getting-started/)。

### CLI 安裝方式

安裝 ESPHome 後，在含 YAML 的目錄執行：

```bash
esphome config bc7215a-c3.yaml
esphome compile bc7215a-c3.yaml
esphome upload bc7215a-c3.yaml --device COM3
esphome logs bc7215a-c3.yaml --device COM3
```

`COM3` 只是 Windows 範例，請換成實際 C3 串口；Linux 可能是 `/dev/ttyUSB0` 或 `/dev/ttyACM0`。若接線與 USB 埠不明，先確認裝置身分再上傳。

## 加入 Home Assistant

1. 讓 HA 主機與 C3 位於可互通的區域網路；初次設定建議同一子網路，避免訪客 Wi-Fi 或 AP 用戶端隔離。
2. 到 **設定 → 裝置與服務**，若看到 ESPHome 裝置已被發現，依提示加入。
3. 若未自動發現，按 **新增整合 → ESPHome**。
4. 主機欄填入日誌中的 **C3 IP 位址**，連接埠填 **6053**。
5. 若自訂設定啟用了 API 加密，輸入對應金鑰；原始範例沒有配置加密金鑰。
6. 加入後開啟該裝置頁面，即可看到空調、操作按鈕及狀態感測器。

填入的是 C3 的 IP，不是 HA 主機 IP。操作電腦與 C3 不同網段不一定會阻止 HA 連線；關鍵是 **HA 主機能否連到 C3 的 TCP 6053**。

ESPHome Device Builder 負責建置與更新韌體；HA 的 ESPHome 整合負責連接裝置。兩者用途不同。參閱 [HA ESPHome 整合說明](https://www.home-assistant.io/integrations/esphome/)。

## 配對冷氣

本版需要原廠遙控器取樣，沒有品牌下拉選單，也不會從全碼庫逐組發送試配。

1. 先確認「運作狀態_Status」沒有通訊故障。將 BC7215A 放在可以接收遙控器訊號的位置。
2. 將原廠遙控器設為 **開機、冷房、25°C**。
3. 在 HA 按 **開始配對_Pair**。C3 彩燈開始七彩循環。
4. 對準 BC7215A 接收頭，按一下遙控器的 **風速鍵**，送出設定。
5. 查看「運作狀態_Status」。若要求補充取樣，照提示操作，例如先調到 24°C 再升回 25°C，或切換模式後回到冷房。
6. 看到 **配對已保存** 後，確認「已配對_Paired」為開啟；離開配對流程後彩燈熄滅。
7. 用原廠遙控器改變溫度，確認 HA 能同步；再從 HA 試送調溫、風速與開關，確認冷氣實際反應。

若有配對成功但控制錯誤，按 **下一個匹配_NextMatch**，查看狀態提示並重新測試該候選。此按鈕在本次取樣的候選中切換，不是全碼庫的下一把遙控器。

需要停止取樣時按 **取消配對_CancelPair**。若一直無法匹配，確認發送的是冷房 25°C 的完整訊號；收到紅外訊號不代表碼庫一定支援該冷氣。

### 如何辨識配對結果

| 實體 | 如何使用 |
| --- | --- |
| 候選序號_Match | 例如「候選 01／共 03 個」，表示這次取樣可匹配的候選；若顯示「至少」，數量只是下限 |
| 配對資料識別碼_PairingID | 本專案產生的配對資料指紋，用於區分已保存的配對資料；不是原廠品牌名或全球通用碼庫編號 |
| 碼庫版本_LibraryVersion | 確認裝置使用的原廠碼庫版本 |
| 已配對_Paired | 是否有可用配對 |
| 本次已同步_StateKnown | 輔助判斷目前設定是否已在本次運作中建立；不代表冷氣主機已回覆 |

不同品牌都出現「候選 01」是正常的：候選序號只在各自的取樣結果內排序。候選總數也不是某品牌所有遙控器型號的數量。

## 日常控制

在 HA 開啟 **空調_AC**，或將該實體加入儀表板的恆溫器卡片。

- **模式**：關閉、自動、冷房、暖房、除濕、送風。
- **設定溫度**：16～30°C，每次 1°C。
- **風速**：自動、低、中、高。
- **擺風**：關閉、上下、左右，需先完成對應學習。

選單列出的項目不等於每台冷氣都支援。冷專機不會因選擇暖房而具備暖房；除濕、自動模式的溫度或風速限制仍依機種而定。

BC7215A 的發射頭要朝向冷氣接收窗，避免被外殼、家具遮住。用原廠遙控器操作時，訊號也要能被 BC7215A 接收到，HA 才有機會同步。

重開機可載入保存的配對，但無法讀回冷氣真實狀態。請先用原廠遙控器送出一筆完整設定，確認 HA 同步後再操作。

## 上下／左右擺風學習

擺風需在冷氣配對並保存成功後進行。每個方向分別記錄一筆「關」和一筆「開」，另一個方向保持關閉。

以上下擺風為例：

1. 冷氣保持開機，遙控器設定冷房 25°C、固定風速，左右擺風關閉。睡眠、定時、強力等附加設定也保持關閉。
2. 在 HA 按 **學習上下擺風_LearnVertical**。
3. 依提示準備「上下擺風關」；準備時不要按擷取。待訊號接收結束後，按 **擷取擺風樣本_CaptureSwing**，再從遙控器送出上下擺風關閉的完整訊號。
4. HA 提示下一步後，維持相同溫度、模式與風速，按 **擷取擺風樣本_CaptureSwing**，再送出上下擺風開啟的完整訊號。
5. 狀態顯示 **已學習，待實機確認效果** 後，在空調實體切換上下／關閉，觀察葉片與其他設定是否正確。
6. 若要學左右，按 **學習左右擺風_LearnHorizontal**，以上下關閉為條件重複流程。

若遙控器只提供切換鍵，可在按擷取前先準備相反狀態，讓正式擷取的那一次按鍵送出所需狀態。每次擷取只按一下，不要長按。可使用 **取消擺風學習_CancelSwing** 中止流程；長時間未完成也會逾時。

注意：

- 適用可解析的完整狀態訊號；獨立短切換碼或不相容封包可能無法學習。
- 本版不提供「上下與左右同時開」。選上下預期為上下開、左右關；選左右則相反。
- 學習完成不代表已確認冷氣確實支援或執行，必須試送驗證。
- 收到原廠遙控器訊號時，只有樣本能唯一辨識，才會同步擺風選項。
- 無法辨識時「擺風狀態_SwingState」會顯示未知，空調選單可能保留上次選項，請以狀態文字一起判讀。
- 這不是未知冷氣的通用學習模式；完全無法匹配碼庫時，不能靠此流程建立完整空調控制。

## 更新與常見問題

### 如何更新

1. 備份自己的 YAML 與 `secrets.yaml`。
2. 用新版完整替換 `components/bc7215a`，並比對、更新 YAML；保留自己的 Wi-Fi 與 USB 日誌設定。
3. 執行 **Clean Build Files／清除建置檔案**，重新編譯。
4. 裝置已連上網路時，可用 **Install → Wirelessly** 進行 OTA 更新。

清除建置檔案只清理編譯產物，不會擦除裝置。碼庫版本改變時，本專案會拒絕直接套用不同版本的舊配對，需要重新配對；擺風資料綁定配對指紋，也可能需要重學。

### 出現 `bc7215a_scan.cpp` 的 `no declaration matches`

這是舊版掃描檔案與新版配對程式混用。v1.0.10-fix1 提供同名空白檔覆蓋舊實作。確認該檔只剩註解，並清除建置檔案後重編。詳細說明見 [編譯錯誤修復說明](編譯錯誤修復說明.md)。

### HA 沒有自動發現

從日誌或路由器確認 C3 IP，手動新增 ESPHome 整合，使用 C3 IP 與 6053。檢查 HA 到 C3 的連通性、防火牆與 Wi-Fi 隔離；Wi-Fi 已連線不代表 API 一定可達。

### BC7215A 無回覆

確認模組供電、共地、TX → GPIO2、RX → GPIO3、MOD → GPIO0、BUSY → GPIO1，以及 19200 8N2。查看診斷日誌後按 **重新檢查通訊_RetryCommunication**。此訊息表示通訊探測失敗，不能僅憑訊息認定接線錯誤。

### 配對成功，但冷氣沒反應

先確認發射方向與距離，再試調溫、模式及風速；必要時切換下一個匹配。HA 設定有改變並不等於紅外指令已被冷氣接收。

### Wi-Fi 連不上

核對 2.4GHz SSID 與密碼。備援熱點啟動後，可連到 `BC7215A-Setup`，使用 `ap_password` 登入；若入口頁沒有自動開啟，可嘗試 `http://192.168.4.1`。同時檢查供電與 Wi-Fi 訊號品質。

### 想學習碼庫沒有的冷氣

目前未實作通用的逐組學習／重播，也不會自動推導未知協議。需要蒐集遙控器樣本進一步確認，不能承諾透過少量按鍵就支援所有模式與溫度。
